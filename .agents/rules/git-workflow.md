# Git Workflow: Обязательные правила

Данный документ фиксирует нерушимый регламент работы с системой контроля версий Git в проекте «Реквием: Последний выстрел» (The Wicked City).

---

## 1. Ветвление и рабочая копия

- **Актуальная рабочая ветка:** Текущая разработка ведётся в рабочей ветке **`feature/tv-party-enhancements`** (или другой согласованной с владельцем рабочей ветке `feature/*` / `agent/*`).
- **Запрет прямой работы в `main`:** Категорически запрещено коммитить напрямую в ветку `main`.
- **Изоляция крупных задач:** Для каждой самостоятельной крупной задачи создаётся отдельная рабочая ветка от актуального состояния.
- **Проверка перед началом:** Перед выполнением любых правок агент обязан проверить активную ветку (`git branch --show-current`) и статус рабочей копии (`git status`).

---

## 2. Фиксация изменений (Commits)

- **Осмысленные логические коммиты:** Изменения группируются по завершённым этапам (например: оптимизация ассетов, безопасность сервера, интерфейс ТВ, очистка тестов).
- **Запрет микро-коммитов:** Не создавать коммит после каждой строчки или единичного изменения файла.
- **Проверка состава:** Перед вызовом `git commit` проверить список индексированных файлов (`git diff --name-only --cached`). В коммит не должны попадать случайные, временные или мусорные файлы.
- **Запрет коммита поломок:** Запрещено коммитить заведомо неработающее состояние, синтаксические ошибки или сломанные тесты без прямого указания владельца.

---

## 3. Операции с удалённым репозиторием (Remote & GitHub)

- **Запрет несанкционированного Push:** Команда `git push` допускается только после проверки изменений и только в рабочую ветку (например, `git push origin feature/tv-party-enhancements`).
- **Запрет Push и Merge в `main`:** Любые операции отправки (`push`) или слияния (`merge`) в ветку `main` требуют **отдельного явного разрешения владельца проекта**.
- **Категорический запрет Force Push:** Команды с ключами `--force` или `-f` (`git push -f`, `git push --force-with-lease`) **строжайше запрещены**.
- **Запрет разрушительных операций:** Запрещено без отдельного разрешения выполнять `git reset --hard`, `git clean -fd`, удалять локальные или удалённые ветки (`git branch -D`, `git push origin --delete`).

---

## 4. Контроль и отчётность

Перед завершением любой задачи агент обязан предоставить владельцу проекта:
1. Список созданных коммитов (`git log`).
2. Список затронутых файлов и краткое объяснение сути правок.
3. Результаты обязательных проверок (тесты, сборка).
4. Запрос разрешения на отправку (push) в удалённую ветку.
