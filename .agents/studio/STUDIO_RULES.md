# Единый регламент AI-студии «Под подозрением (Prime Suspect)»

> **Проект:** «Под подозрением (Prime Suspect)»  
> **Статус:** Официальный регламент разработки  
> **Центр управления:** Antigravity AI-first Platform  

---

## 1. Иерархия и распределение ответственности

1. **Владелец продукта (User / Human Boss):**
   - Единственный источник продуктовых, концептуальных и бизнес-решений.
   - Утверждает планы работ, спецификации новых механик, дизайн-решения и приёмку задач.
   - Не обязан быть программистом: общается на естественном русском языке.
   - Никакой агент не вправе принимать решения за владельца или изменять правила без его согласия.

2. **Главный AI-директор (Studio Director):**
   - Технический координатор и руководитель команды агентов в Antigravity.
   - Декомпозирует задачи владельца на понятные подзадачи.
   - Определяет состав необходимых специалистов.
   - Назначает ответственных за конкретные файлы (принцип «Один файл — один исполнитель»).
   - Контролирует зависимости и предотвращает конфликты.
   - Организует независимый аудит качества через QA Auditor.
   - Формирует прозрачные отчёты для владельца без сложного жаргона.

## 3. Неизменяемые правила и инварианты игры

Каждый агент студии обязан строго соблюдать следующие канонические правила:

1. **Официальное название проекта:**  
   Строго **«Под подозрением (Prime Suspect)»**. Использование устаревших названий (*Requiem*, *Wicked City*, *The Wicked City*) категорически запрещено.
2. **Стилистика портретов:**  
   Персонажи на карточках намеренно представлены **тёмными силуэтами без прорисованных лиц** в эстетике киберпанк/нео-нуар. Запрещено требовать генерации «реалистичных лиц».
3. **Режим TV Party — разделение экранов:**
   - **Экран телевизора (`TvBoardView.tsx`):** Публичное поле 5×5, статус текущей очереди, публичные действия, журнал событий. D-Pad пульт Android TV управляет исключительно меню паузы (ячейки поля не получают фокус).
   - **Мобильный пульт (`MobileControllerView.tsx`):** Персональное досье с биометрической шторкой, мини-карта **3×3 («Ваши соседи»)** с центром в тайной личности игрока. Смартфон **НЕ** показывает всё поле 5×5.
4. **Механика тактического маневра (сдвига линий):**
   - Сдвиг выполняется **циклически на 1 клетку** по выбранному ряду или столбцу. Вытесненная карточка переносится на противоположную сторону.
   - **Никаких карт из руки и никакого выбора персонажей для сдвига!**
   - **Строгий 2-этапный UX:**  
     1. Выбор оси (Горизонталь / Вертикаль) и номера линии (1–5) с live-подсветкой на ТВ (`PREVIEW_SHIFT`).  
     2. Выбор направления (Влево/Вправо или Вверх/Вниз) с мгновенным выполнением в 1 клик и проверкой Anti-Undo.
5. **Фирменный биометрический слайдер:**  
   Слайдер подтверждения («Проведите для старта») на кнопке «Быстрая игра» сохраняется как ключевой тактильный элемент.
6. **Zero Emoji Invariant:**  
   Никаких Unicode-эмодзи в интерфейсе. Все пиктограммы реализуются через векторные SVG-компоненты единого кита.
7. **Строгие визуальные запреты:**  
   - Категорически запрещено использовать кислотные цвета и превращать интерфейс в дешёвый неон.  
   - Запрещено изменять карточки игровых режимов, элементы действий и окантовки статусов без прямого разрешения владельца проекта.  
   - Категорически запрещено удалять или ухудшать удачные анимации.  
   - Запрещено добавлять новые декоративные плашки, чипсы и бейджи без необходимости.

## 4. Регламент параллельной работы и управление Git

### 4.1. Защита пользовательских данных
В репозитории находятся ценные незакоммиченные файлы владельца (оптимизированные ассеты, UI polish, документация).
**Категорически запрещено без отдельного прямого разрешения владельца:**
- `git reset`, `git clean`, `git checkout` (для отката изменений);
- `git stash` (автоматический или ручной);
- создание коммитов, слияние веток (`merge`) или `push`;
- удаление или переименование веток;
- запуск скриптов деплоя (`deploy`, `gh-pages`);
- массовое форматирование или перезапись чужих файлов.

### 4.2. Режим работы: Последовательный vs Изолированные Worktrees
- **Текущий режим работы — Последовательный (Sequential):**  
  Поскольку Git Worktrees создаются на основе коммитов Git, создание нового Worktree сейчас **не перенесёт** в него текущие 68 незакоммиченных файлов working tree.  
  Поэтому до согласования и создания базового коммита релиза v1.0.0 агенты работают **в основном каталоге последовательно** либо используют параллельное исследование в режиме Read-Only.
- **Правило «Один файл — один исполнитель»:**  
  В рамках любой задачи редактировать конкретный файл имеет право только один назначенный агент. Другие агенты могут читать файл, но не менять его одновременно.

## 5. Независимый контроль качества (QA)

1. **Разделение ролей:** QA Auditor никогда не является автором проверяемого кода.
2. **Фактическое подтверждение:** Слова агента «я всё исправил, тесты должны работать» не имеют силы. QA обязан запустить:
   - `npm test` (все 46 файлов тестов, 295 тестов обязаны быть зелёными);
   - `npx tsc --noEmit` (0 ошибок компиляции TypeScript);
   - `npm run build` (успешная сборка PWA).
3. **Право вето:** QA Auditor обязан отклонить задачу и вернуть её исполнителю, если:
   - упал хотя бы один тест;
   - нарушен инвариант правил 4 режимов;
   - обнаружен layout shift или регрессия производительности;
   - тесты были пропущены (`test.skip`).
