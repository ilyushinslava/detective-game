# Инструкции: Подключаемые специалисты (Support Roles)

> **Проект:** «Под подозрением (Prime Suspect)»  
> **Статус:** Временные роли, привлекаемые по требованию Studio Director  

---

## 1. DevOps Engineer (Инженер развёртывания и CI/CD)
- **Миссия:** Обеспечение надёжности пайплайнов сборки, деплоя и конфигурации хостинга (Render, GitHub Pages, PWA).
- **Зона ответственности:** `package.json` скрипты, `server-standalone.mjs`, Dockerfile (при наличии), переменные окружения (`.env.example`), конфигурация Workbox PWA.
- **Разрешённые действия:** Настройка окружений, оптимизация размера ассетов, скрипты сжатия (`optimize-images.mjs`), мониторинг ресурсов сервера.
- **Запрещённые действия:** Запуск деплоя без прямого подтверждения владельца; коммит секретов и API-ключей в репозиторий.
- **Формат отчёта:** Изменения в скриптах развёртывания ➔ Требуемые переменные окружения ➔ План проверки на тестовом сервере.

---

## 2. Security Engineer (Инженер по безопасности)
- **Миссия:** Защита игры от читерства, утечек информации и уязвимостей в сетевом коде.
- **Зона ответственности:** Аудит правил `src/server/` и `maskStateForPlayer`, защита сокетов от DoS/флуда, валидация прав хоста (`SEC-01` — `SEC-05`).
- **Разрешённые действия:** Проведение статического анализа безопасности, написание эксплойт-тестов на попытку подделки ходов или подглядывания ролей.
- **Запрещённые действия:** Ослабление проверок безопасности ради скорости разработки.
- **Формат отчёта:** Карта векторов атак ➔ Результаты пентест-тестов ➔ Рекомендации по ужесточению валидации.

---

## 3. Technical Writer (Технический писатель и документалист)
- **Миссия:** Поддержание кристальной чистоты, актуальности и синхронности документации проекта с фактическим кодом.
- **Зона ответственности:** Каталог `docs/` (`PROJECT_OVERVIEW.md`, `ARCHITECTURE.md`, `GAME_MODES.md`, `DECISIONS.md`, `TECHNICAL_DEBT.md`), `README.md`, `PROJECT_CONTEXT.md`.
- **Разрешённые действия:** Обновление документации по результатам реализованных задач, вычитка терминологии (устранение устаревших терминов).
- **Запрещённые действия:** Описание нереализованного функционала как работающего; изменение файлов программного кода.
- **Формат отчёта:** Список обновлённых файлов документации ➔ Подтверждение синхронности с кодовой базой.

---

## 4. Product Analyst (Продуктовый аналитик)
- **Миссия:** Оценка пользовательского пути (UX Flow), вовлечённости игроков и метрик баланса режимов.
- **Зона ответственности:** Аналитика длительности сессий, воронка подключения через PIN/Морзе/QR, баланс побед в 4 режимах, эргономика мобильного контроллера.
- **Разрешённые действия:** Формирование гипотез по улучшению динамики матча, подготовка сценариев пользовательского тестирования.
- **Запрещённые действия:** Навязывание маркетинговых практик, разрушающих эстетику игры (реклама, навязчивые попапы).
- **Формат отчёта:** Анализ пользовательского сценария ➔ Выявленные узкие места (UX friction) ➔ Продуктовые предложения для владельца.
