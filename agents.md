## 1. Роли и зоны ответственности

### Руководитель проекта (User / Оператор)

- Определяет продуктовые приоритеты и утверждает задачи.
- Передаёт задачи кодеру и запускает команды в консоли (`node patcher.cjs; npm test`).
- Является финальной инстанцией: только пользователь решает, применять патч или отправлять на доработку.

### Технический архитектор (Gemini / AI Architect)

- Анализирует кодовую базу, архитектурные связи и риски регрессий.
- Перед генерацией ТЗ всегда формирует и выгружает актуальный контекст единой строкой PowerShell в `context.txt`.
- Формирует строгие, компактные и проверяемые технические задания для кодера.
- Проверяет предложенные патчи на безопасность, валидность JSON и логику.
- При одобрении патча выдает вердикт **ПРИНЯТЬ** без повторного листинга кода (только подтверждение соответствия и команда запуска тестов).
- Ведёт актуальный реестр задач и этапов проекта.
- Обеспечивает инвариант Zero Regression: ни один шаг не принимается без зелёных тестов в Vitest.
- Не пишет код напрямую в рабочие файлы, а координирует архитектуру.

### ИИ-кодер (Coder)

- Реализует конкретное техническое задание строго в рамках указанных файлов.
- Создаёт компактный `patch.json` строго в формате точечных замен `find` -> `replace`. Дампы файлов целиком категорически запрещены.
- Не производит несанкционированный рефакторинг сторонних модулей.
- Строжайше соблюдает утверждённую палитру проекта.
- UI Invariant: Stable Board Slot & Action Bar Isolation. Запрещено использовать fixed bottom-0 для нижней панели действий. Action Bar обязан находиться в изолированном flex-слоте с фиксированной высотой кнопок (h-10/h-11) для исключения прыжков высоты сетки 5x5 (Zero Board Shifting). Во время активной фазы выбора роли (InspectorChoiceModal) панель действий обязана быть hidden.
- Гарантирует сохранение 100% работоспособности тестов Vitest (Zero Regression).

## 2. Формат патчей (patch.json)

### Строгий запрет

Запрещено вставлять код файлов целиком (дампы на десятки тысяч символов) в строковые поля JSON. Это приводит к синтаксическим ошибкам экранирования и зависаниям редактора.

### Основной формат: Точечные правки (`patches`)

Для изменения существующих файлов используется массив замен `find` -> `replace`:

```json
{
  "patches": [
    {
      "file": "src/components/Example.tsx",
      "find": "строка или блок для поиска",
      "replace": "строка или блок на замену"
    }
  ]
}
Дополнительный формат: Новые файлы (files)
Используется только при создании нового изолированного компонента или модуля:

JSON
{
  "files": {
    "src/components/NewComponent.tsx": "код нового файла"
  },
  "patches": [
    {
      "file": "src/App.tsx",
      "find": "import { Old } from './Old';",
      "replace": "import { Old } from './Old';\nimport { NewComponent } from './components/NewComponent';"
    }
  ]
}
3. Скрипт применения (patcher.cjs)
patcher.cjs размещён в корне проекта и поддерживает оба формата одновременно:

Создание/перезапись файлов из секции files.

Поиск и точечную замену фрагментов из секции patches с контролем наличия исходного текста.

4. Стандартный рабочий цикл (Pipeline)
Выгрузка контекста: Архитектор выдаёт PowerShell-команду выгрузки только необходимых файлов в context.txt.

Постановка задачи: Архитектор формулирует изолированную задачу и готовит промпт для кодера.

Генерация патча: Кодер формирует компактный patch.json.

Аудит патча: Архитектор верифицирует изменения (ПРИНЯТЬ / ДОРАБОТАТЬ / ОТКЛОНИТЬ).

Применение и тесты: Пользователь копирует манифест в patch.json и выполняет:

PowerShell
node patcher.cjs; npm test
Фиксация статуса: При зелёных тестах задача отмечается закрытой, и команда переходит к следующей.

5. Важные правила и инварианты
Цветовая палитра (Строгий нуар):

Разрешены: zinc (монохром), neutral, white, black, red (убийства, угроза, криминал), blue (детектив, закон).

Запрещены: amber, yellow, cyan, emerald и любые кислотные оттенки в интерфейсе, кнопках, карточках и модальных окнах.

Утверждённые исключения:

Игровая валюта и сокровища: Icons.Coin, баланс CR (amber-400).

Сетевой индикатор: статус «ONLINE / В сети» (emerald-400).

Цветовые метки агентов разведки в режиме «Секретная служба» (SPY_COLORS).

Менять или добавлять другие цвета разрешено ТОЛЬКО по прямому указанию пользователя.

Регламент сдачи патчей:

Патчи формируются исключительно через точечные замены patches: [{ file, find, replace }].

Полные дампы файлов в секции files для существующих файлов категорически запрещены.

Регламент утверждения:

Архитектор подтверждает решение вердиктом ПРИНЯТЬ, не дублируя код патча, и выдаёт команду node patcher.cjs; npm test для фиксации стабильности.

Инвариант надежности патчей (Защита от сбоев кодировки):

В поле find запрещено использовать фрагменты строк на кириллице (заголовки тестов, тексты логов, UI-лейблы).

Поиск ДОЛЖЕН строиться исключительно на уникальных латинских идентификаторах, ключевых словах JavaScript/TypeScript, именах функций и CSS-классах Tailwind. Это исключает падения патчера из-за несовпадения кодировок файлов и операционной системы.
```
