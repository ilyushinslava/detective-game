## 2. Клиентский слой (Frontend)

### Роутинг и экраны в `App.tsx`
Приложение функционирует как единое SPA, где экран выбирается на основе параметров URL и внутреннего состояния:

   - `?clientType=TV_DISPLAY&room=XXXXX` — автоматически переводит приложение в режим **главного экрана телевизора**.
   - `?clientType=CONTROLLER&room=XXXXX` — переводит телефон в режим **мобильного контроллера**.

Включает модульную сетку `LobbyGrid.tsx` (3 карточки: Одиночные дела PVE, На одном экране PVP, широкий ТВ Режим), стилизованные `ModeCard.tsx` (outline-стиль без заливки, `border-white/20`) и правый пульт `NetworkSidebar.tsx` (Inset Terminal Deck: `bg-black/60 border border-white/10 shadow-[inset_0_2px_25px_rgba(0,0,0,0.9)] backdrop-blur-2xl` с биометрическим слайдером и доступом к комнатам).

   - `TablesScreen.tsx` — независимый экран сетевого радара открытых и приватных комнат с защитой Морзе-шифром.
   - `ProfileScreen.tsx` — личный профиль детектива, статистика побед, уровень, рейтинг (MMR), история матчей и блок безопасного сохранения аккаунта (логин/пароль).

## 3. Серверная архитектура (PartyKit & Standalone)

Серверная часть спроектирована универсально: она может работать как в бессерверной среде Cloudflare/PartyKit, так и в стандартном контейнере Node.js.

### Двойной запуск сервера:
1. **Режим разработки (PartyKit CLI):**
   ```bash
   npm run party:dev # или npm run server:start
   ```
2. **Автономный сервер для облака (Render):**
   `server-standalone.mjs` — независимый Node.js runner на библиотеке `ws` и HTTP, использующий `jiti` для динамической загрузки `src/server/index.ts` без предварительной компиляции. Развёрнут на Render (`detective-game-haxi.onrender.com`).

### Жизненный цикл комнаты (`ServerRoomState`):
- `EMPTY` — комната создана, ожидает хоста.
- `WAITING` — хост подключился, комната зарегистрирована в реестре `publicRoomsRegistry` и ждёт второго игрока/телевизор.
- `READY_TO_START` — требуемое количество участников набрано, ожидается подтверждение готовности.
- `PLAYING` — матч активен, сервер валидирует и диспатчит действия в `gameReducer`.
- `FINISHED` — матч завершён, зафиксирован победитель.

### Сетевой протокол сообщений (WebSocket Protocol):

1. **Сетевые и управляющие запросы (Клиент ➔ Сервер):**
   - `PING` — проверка доступности канала связи (сервер отвечает `PONG`).
   - `RESOLVE_ROOM` — поиск комнаты по 7-символьному коду Морзе (`morseCode`) или коду лобби (`roomCode`).
   - `START_MATCH` — запуск матча. Право на отправку имеют **только создатель комнаты (Host)** либо **экран телевизора (`TV_DISPLAY`)**. Обычный подключившийся игрок (гость) не имеет права запускать матч: при попытке отправки сервер отклоняет запрос с ошибкой `ACTION_REJECTED: NOT_HOST`.
   - `CHANGE_SETTINGS` — смена игрового режима в лобби (разрешено только хосту).
   - `REQUEST_RESTART`, `CONFIRM_RESTART`, `REJECT_RESTART` — согласование реванша после завершения матча (с валидацией прав хоста и взаимного согласия сторон).
   - `PLAYER_LEFT_EXPLICIT` — явное уведомление о выходе игрока из комнаты.

2. **Интерактивные сетевые события предпросмотра (Клиент ➔ Сервер ➔ Все клиенты):**
   - `PREVIEW_SHIFT` — актуальное сетевое событие предварительного просмотра маневра (сдвига линии). Отправляется мобильным контроллером при выборе оси и индекса линии (`{ type: 'ROW' | 'COL', index: number }`). Сервер транслирует его всем участникам комнаты через `broadcastRaw` без модификации внутреннего состояния `gameState`, благодаря чему экран ТВ (`TvBoardView.tsx`) мгновенно отображает live-подсветку линии.
   - `LINE_PREVIEW` — legacy-алиас предварительного просмотра сдвига линии (со структурой `{ line: { type, index } }`), сохранённый на сервере для обратной совместимости с ранними клиентами и тестами.

3. **Игровые действия (Клиент ➔ Сервер, передаются в `gameReducer`):**
   - Действия активного хода: `SHIFT_BOARD` (выполнение маневра линии поля), `TARGET_KILL` (покушение маньяка), `CHECK_ALIBI` (проверка алиби детективом), `ARREST` (арест подозреваемого), `STEAL` (кража сокровища вором), `DISGUISE` (смена маскировки), `ESCAPE_DISGUISE` (сброс маскировки), `CALL_PATROL` (вызов патруля), `CAPTURE_SPY` (захват агента), `INTERROGATE_SPY` (допрос связного), `ASK_QUESTION` (допрос свидетеля), `ACCUSE` (финальное обвинение) и др.
   - *Серверная валидация:* Сервер строго проверяет очерёдность хода (`NOT_YOUR_TURN`), роль отправителя и фазу раунда.
   - *Инвариант безопасности:* Соединению `TV_DISPLAY` запрещено отправлять любые игровые действия (все они блокируются сервером; единственное исключение для ТВ — запуск матча `START_MATCH`).

4. **Серверные ответы и оповещения (Сервер ➔ Клиент / Broadcast):**
   - `AUTH_TOKEN` — криптографический токен сессии для восстановления при разрыве связи.
   - `ROOM_RESOLVED` / `RESOLVE_FAILED` — ответ клиенту на запрос `RESOLVE_ROOM` с метаданными лобби или ошибкой `ROOM_NOT_FOUND`.
   - `ROOM_STATUS` — широковещательное обновление списка участников, статуса готовности и позывного Морзе.
   - `GAME_STATE` — трансляция авторитетного состояния игры после применения действия в `gameReducer` (персонально маскируется для каждого клиента и для ТВ).
   - `PREVIEW_SHIFT` — широковещательная ретрансляция подсветки линии на экране ТВ.
   - `TURN_TIMER_PAUSED`, `TURN_TIMER_RESUMED`, `TURN_TIMEOUT` — синхронизация и срабатывание блиц-таймера.
   - `ACTION_REJECTED` — персональный отказ в выполнении действия с указанием конкретной причины (`NOT_YOUR_TURN`, `NOT_HOST`, `INVALID_PHASE`, `MATCH_NOT_FINISHED`, `NOT_AUTHORIZED_RESTART`).
   - `ERROR` — сетевые ошибки (`MAX_TV_REACHED`, `ROOM_FULL`, `ROOM_NOT_FOUND`).
   - `PRESENCE_CHANGED`, `OPPONENT_LEFT`, `TV_DISCONNECTED`, `MATCH_ANNULLED` — управление дисконнектами и тайм-аутом ожидания переподключения.

### 3.1. Сессии мобильного контроллера и аварийный выход (Teardown & Emergency Exit)
- **Управление сессией:** При подключении к ТВ данные сессии сохраняются в `localStorage` (`tv_session_party_state`, `tv_session_room_code`, `tv_controller_client_id`). Сессия сохраняется только при наличии активного кода комнаты (`tvRoomCode`).
- **Защита от застревания в лобби (Dead Room Protection):** При получении `TV_DISCONNECTED`, `OPPONENT_LEFT`, статуса комнаты с `hasTvDisplay: false` или ошибки `ROOM_NOT_FOUND` контроллер разрывает соединение, полностью очищает ключи сессии из `localStorage` / `sessionStorage` и возвращает игрока на экран подключения с баннером «ТВ-хост отключился».
- **Ручной аварийный выход:** На экране ожидания лобби предусмотрена эргономичная кнопка «ПОКИНУТЬ ЛОББИ» (touch target $\ge 48\text{px}$), принудительно вызывающая `partyService.disconnect()`, сбрасывающая URL-параметры и очищающая локальную сессию.

### 3.2. Оффлайн-режим Pass & Play и шторка приватности (Blindfold Curtain)
- **Локальный движок (Local Game Engine, `useLocalGame.ts`):** В режиме оффлайн-дуэли (`opponent === "PVP"` или при игре на одном устройстве) действия обрабатываются локальным редьюсером `gameReducer` без отправки сетевых пакетов на сервер.
- **Процедурное аудио (`tvAudio.ts`):** При локальных ходах синтезируются процедурные звуки Web Audio API (`playShiftSound`, `playEliminateSound`, `playRadarPing`, `playClickSound`), обеспечивая нулевую задержку и автономность от внешних аудиофайлов.
- **Фаза пересменка (`INTERSTITIAL`):** При смене хода между игроками стейт переходит в фазу `INTERSTITIAL` и активирует полноэкранную шторку `BlindfoldCurtain` (`z-[9999]`, абсолютный черный фон).
- **Снятие шторки:** Шторка скрывает секретные роли и расклад поля до момента, пока новый игрок явно не коснётся экрана ("НАЖМИТЕ НА ЭКРАН ДЛЯ ПРОДОЛЖЕНИЯ"). Снятие сопровождается тактильным импульсом (Haptic) и процедурным кликом.
- **Эргономика интерфейса:** Игровое поле 5×5 центрировано на экране, панель действий расположена снизу под пальцем, карточки ролей скрывают секреты по принципу press-and-hold (peek).

## 4. Безопасность и античит (Многоуровневый комплекс «Стальной Щит»)

Комплекс безопасности игры спроектирован по принципу эшелонированной обороны (Defense-in-Depth):

### 4.1. Серверная фильтрация состояния (State Masking & Cheat Prevention):
Перед трансляцией состояния клиентам через WebSocket сервер выполняет обязательную фильтрацию:
1. **`maskStateForPlayer(state, role, isHost)`:**
   - Скрывает секретные ID персонажей соперника (`killerSecretId` / `detectiveSecretId` / чужие `spies[i].secretId`).
   - Очищает руки карт оппонента (`detectiveHand` / `killerHand`).
   - Очищает колоду улик (`evidenceDeck`).
   - Маскирует будущие цели маньяка в очереди `victimList` строками `"UNKNOWN"`, оставляя открытой только текущую цель `[0]`.
2. **`maskStateForTv(state)`:**
   - Полностью очищает все секретные роли, колоды и руки, так как экран ТВ публичен.
   - Оставляет только общее поле 5×5, статус хода, открытые жетоны и протокол действий.
3. **Защита сокета TV_DISPLAY:**
   - Сервер блокирует любые игровые действия, если они отправлены с соединения ТВ (единственное разрешённое действие для `TV_DISPLAY` — запуск матча `START_MATCH`).

### 4.2. Безопасность базы данных Supabase (RLS, Column Grants & Trigger):
1. **Ограничение уровня колонок (Column-Level Grants):**
   - Прямой `UPDATE` для роли `authenticated` разрешён ТОЛЬКО для полей `agent_name` и `avatar_id`.
2. **Триггер `protect_profile_stats`:**
   - Любая попытка подделать `mmr`, `cash`, `xp`, `level`, `rank`, `matches_played` или счетчики побед блокируется на уровне ядра PostgreSQL (код `42501`, 403 Forbidden).
3. **Хранимая функция (RPC) `record_match_result` с античитом:**
   - **Анти-спидхак:** Проверяет `duration_seconds > 10`. Мгновенные победы отклоняются (код `P0001`, 400 Bad Request).
   - **Анти-повтор (Anti-Replay):** Уникальный композитный индекс `(match_id, profile_id)` исключает повторную отправку победы за один и тот же матч (код `23505`, 409 Conflict).

### 4.3. Сетевой валидатор пакетов (P2P / PartyKit):
1. **Функция `parseAndValidatePacket(raw)`:**
   - Проверяет синтаксис типа пакета по белому списку формата `/^[A-Z0-9_]{3,50}$/`.
   - Защита от **Prototype Pollution**: строки, содержащие ключи `"__proto__"`, `"constructor"` или `"prototype"`, отбрасываются (Drop) без парсинга, предотвращая загрязнение глобального прототипа.
   - Блокировка XSS: пейлоады с тегами `<script>` или инъекциями кода отсекаются до передачи в редьюсер.
2. **Безопасность парсинга:**
   - Любой невалидный или поврежденный JSON перехватывается блоком `try/catch` и молча отбрасывается без сбоя клиентского приложения.

### 4.4. Изоляция DevTools в Production:
- Компонент отладки `DevPanel` и кнопки читов обёрнуты в проверку `if (import.meta.env.DEV)`.
- Сборщик Vite при компиляции `npm run build` физически исключает код дев-панели из клиентского бандла (Tree-shaking). Горячие клавиши отладки отключены.

## 5. Хранилище данных и облачная синхронизация (Storage Architecture)

Система построена по гибридной архитектуре **Offline-First с облачной синхронизацией**:
1. **Локальное хранилище:** `IndexedDB` (база `requiem_game_db`, хранилище `key_val`) с автоматической миграцией устаревших ключей из `localStorage`. Игра сохраняет 100% автономность без подключения к сети.
2. **Облачная база (Supabase):** 
   - Таблицы `profiles`, `matches`, `match_participants`.
   - Авторизация по логину/паролю без сбора Email-адресов (`@noir.local`).
   - Рейтинговая система (MMR) и история последних матчей.
3. **Отказоустойчивость (Graceful Degradation):**
   - При отсутствии переменных `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` клиент плавно переключается на встроенный mock-клиент без прерывания пользовательского сценария.

## 6. Звук, вибрация и PWA

- **Звуковая подсистема (`audio.ts`):** Реализована через Web Audio API с программным синтезом звуков (выстрел, маневр, сирена, клики, непрерывный аналоговый тон Морзе на 700 Гц) без обязательной загрузки тяжёлых внешних mp3-файлов.
- **Тактильный отклик (`haptics.ts`):** Использует `navigator.vibrate` с набором тактильных паттернов (лёгкий клик, предупреждение, успех, тревога) и безопасной проверкой поддержки браузером.
- **PWA (Progressive Web App):** Настроен через `vite-plugin-pwa` в `vite.config.ts`. Прекэширует ключевые ресурсы приложения (по состоянию контрольной сборки релиза v1.0.0: 103 файла, ~7.8 МиБ; метрика отражает текущий объём ресурсов и меняется при добавлении новых ассетов), обеспечивая мгновенный запуск офлайн и возможность установки игры на рабочий стол смартфона или Android TV.

## 7. Фронтенд-архитектура визуального слоя и дизайн-системы Neo-Noir

1. **Цветовая палитра и инварианты:**
   - **Базовый фон:** глубокий угольно-черный `#080a0f` и `#06070a`, монохромные оттенки `zinc-100`..`zinc-900`.
   - **Сторона Закона (Детектив, Оперативник):** благородный глубокий сапфирово-синий (`#1E3A8A`, `#2563EB`, `#3B82F6`). Циан и бирюза исключены из роли Закона.
   - **Сторона Угрозы (Маньяк, Криминал, Тревога):** приглушенный темно-бордовый и глубокий винный (`#2d0814`, `#881337`, `#9f1239`).
2. **Строгие визуальные ограничения:**
   - **Запрет кислотных цветов:** категорически запрещены кислотные оттенки (ядовитый циан, лайм, открытый розовый/маджента, едкий фиолетовый).
   - **Запрет стробоскопических анимаций:** анимации фонов (`LiquidBackground`) используют мягкие радиальные затухания, длительный медитативный цикл (24–28 секунд) и GPU-ускорение без эффекта резкой полицейской мигалки.
