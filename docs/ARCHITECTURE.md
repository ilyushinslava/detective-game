# Архитектура проекта: «Под подозрением (Prime Suspect)»

> **Статус:** Актуальная техническая спецификация системы (Релиз v2.0.0)  
> **Стек:** React 18, TypeScript (строгий режим `noImplicitAny`, `strictNullChecks`), Tailwind CSS, Framer Motion, Supabase (PostgreSQL, RLS, RPC), PartyKit WebSocket, Vite, IndexedDB, Capacitor 8.  
> **Тесты:** 95 сьютов, 618 тестов (100% pass) + GitHub Actions CI.

## 2. Клиентский слой (Frontend)

### Роутинг и экраны в `App.tsx`
Приложение функционирует как единое SPA, где экран выбирается на основе параметров URL и внутреннего состояния:
1. **Параметры URL:**
   - `?clientType=TV_DISPLAY&room=XXXXX` — автоматически переводит приложение в режим **главного экрана телевизора**.
   - `?clientType=CONTROLLER&room=XXXXX` — переводит телефон в режим **мобильного контроллера**.
2. **Основные экраны и декомпозиция интерфейса:**
   - `SplashScreen.tsx` — заставка загрузки с анимацией.
   - `MainMenu.tsx` — главное меню (ранее «Штаб»). Включает модульную сетку `LobbyGrid.tsx` (3 карточки: Одиночные дела PVE, На одном экране PVP, широкий ТВ Режим), стилизованные `ModeCard.tsx` (outline-стиль без заливки, `border-white/20`) и правый пульт `NetworkSidebar.tsx` (Inset Terminal Deck: `bg-black/60 border border-white/10 shadow-[inset_0_2px_25px_rgba(0,0,0,0.9)] backdrop-blur-2xl` с биометрическим слайдером и доступом к комнатам).
   - `LobbyBottomNav.tsx` — нижний навигационный бар: строго 3 равные вкладки («Главное меню», «Сеть», «Досье») с симметричными иконками 24×24px. Мультиплеер изолирован от главного экрана.
   - `TablesScreen.tsx` — независимый экран комнат открытых и приватных столов с защитой кодом Морзе.
   - `ProfileScreen.tsx` — личный профиль детектива: статистика побед, уровень, рейтинг (MMR), история матчей, блок безопасного сохранения аккаунта (логин/пароль) и вкладка 18 достижений (`ProfileAchievements.tsx`).
   - `LoginModal.tsx` — окно авторизации для восстановления профиля на любом устройстве.
   - `GameScreen.tsx` — стандартный экран с карточками персонажей, игровой доской `GameBoard.tsx` и нижней панелью действий (стрелки маневра поля следуют Board Shift Arrows Contract: строго белая вспышка на 250 мс, запрет персистентного свечения).
   - `TutorialScreen.tsx` — Академия детективов v2 (3 канонических дела, 11 объединённых шагов `CARD_ACTION`, неподвижная 4-слотовая вёрстка Zero-Jump в `100dvh`).
   - `DuelScreen.tsx` — режим «Очная ставка» (`LINE_UP`): **[ЗАМОРОЖЕН / В РАЗРАБОТКЕ]**, скрыт из активного меню и турнирной ротации до отдельного редизайна.
   - `TvBoardView.tsx` — 3-колоночный экран для телевизора с поддержкой пульта D-Pad (фокус меню паузы) и live-подсветкой маневра.
   - `TvLobbyView.tsx` — экран ожидания игроков на ТВ: чистый QR-код, оптический код Морзе с крупными неоновыми пилюлями, выбор формата (с телефонами / Pass & Play) и кнопка «В МЕНЮ» в правом верхнем углу (5-значный PIN удалён).
   - `ControllerConnectView.tsx` — экран подключения смартфонов к ТВ: авторизация через сканирование QR-камерой либо тактический ввод позывного Морзе с оригинальными аудиосэмплами из `public/sounds/`.
   - `MobileControllerView.tsx` — мобильный пульт: пространственная мини-карта 3×3 («Ваши соседи»), 2-этапный плавающий док маневра линий поля (Zero Layout Shift), экран ожидания («режим радиомолчания» с биометрической шторкой досье), личный автономный блокнот детектива и кнопка аварийного выхода.
   - `TvNetworkDisconnectModal.tsx` & `OfflineFallback.tsx` — отказоустойчивые оверлеи потери связи (`z-[70]` и `z-[10000]`) с гарантированной кнопкой «В МЕНЮ (ОТМЕНА)», принудительно прерывающей reconnect-цикл и очищающей URL.
   - `PwaUpdateToast.tsx` — ненавязчивое уведомление о выходе новой версии приложения (`registerType: "prompt"`).

   - `src/hooks/useLobbyNetwork.ts` — управление сетевыми комнатами, создание столов, автоопрос комнат и валидация кодов.
   - `src/hooks/useHaptics.ts` — эргономичный React-хук тактильной отдачи с мемоизированными методами вызова.

2. **Сетевые и служебные модули (`src/utils/`):**
   - `src/utils/partyPeer.ts` — синглтон управления WebSocket-соединением (`PartyService`), функция безопасного парсинга `parseAndValidatePacket`.
   - `src/utils/storage.ts` — безопасный фасад `safeLocalStorage`, `safeSessionStorage` и IndexedDB `requiem_game_db`.
   - `src/utils/audio.ts` — 2-канальный менеджер `soundManager` (UI и Action каналы, дебаунс 70 мс, 25 оригинальных mp3 сэмплов).
   - `src/utils/haptics.ts` — ядро кроссплатформенной тактильной отдачи на Capacitor Haptics с безопасным каскадом веб-фоллбэков.

3. **Интернационализация и аутентификация:**
   - `src/contexts/AuthContext.tsx` — контекст анонимной авторизации и привязки аккаунта по логину/паролю без сбора персональных данных (`@noir.local`).
   - `src/i18n/context.tsx` — типизированный React-провайдер интернационализации (`useTranslation`, `useLanguage`) со словарями `ru.ts` и `en.ts`.

## 3. Серверная архитектура (PartyKit & Standalone)

Серверная часть спроектирована универсально: она может работать как в бессерверной среде Cloudflare/PartyKit, так и в стандартном контейнере Node.js.

### Двойной запуск сервера:
1. **Режим разработки (PartyKit CLI):**
   ```bash
   npm run party:dev
   ```
2. **Автономный сервер для облака (Render):**
   `server-standalone.mjs` — независимый Node.js runner на библиотеке `ws` и HTTP, использующий `jiti` для динамической загрузки `src/server/index.ts` без предварительной компиляции. Развёрнут на Render (`detective-game-haxi.onrender.com`).

### Жизненный цикл комнаты (`ServerRoomState`):
- `EMPTY` — комната создана, ожидает хоста.
- `WAITING` — хост подключился, комната зарегистрирована в реестре `publicRoomsRegistry` и ждёт второго игрока/телевизор.
- `READY_TO_START` — требуемое количество участников набрано, ожидается подтверждение готовности.
- `PLAYING` — матч активен, сервер валидирует и диспатчит действия в `gameReducer`.
- `FINISHED` — матч завершён, зафиксирован победитель.

### Сетевой протокол сообщений (WebSocket Protocol):

1. **Сетевые и управляющие запросы (Клиент ➔ Сервер):**
   - `PING` — проверка доступности канала связи (сервер отвечает `PONG`).
   - `RESOLVE_ROOM` — поиск комнаты по 7-символьному коду Морзе (`morseCode`) или коду лобби (`roomCode`).
   - `START_MATCH` — запуск матча. Право на отправку имеют **только создатель комнаты (Host)** либо **экран телевизора (`TV_DISPLAY`)**. Обычный подключившийся игрок (гость) не имеет права запускать матч (`ACTION_REJECTED: NOT_HOST`).
   - `CHANGE_SETTINGS` — смена игрового режима в лобби (разрешено только хосту).
   - `REQUEST_RESTART`, `CONFIRM_RESTART`, `REJECT_RESTART` — согласование реванша после завершения матча.
   - `PLAYER_LEFT_EXPLICIT` — явное уведомление о выходе игрока из комнаты.

2. **Интерактивные сетевые события предпросмотра (Клиент ➔ Сервер ➔ Все клиенты):**
   - `PREVIEW_SHIFT` — сетевое событие предварительного просмотра маневра (сдвига линии). Отправляется мобильным контроллером при выборе оси и индекса линии (`{ type: 'ROW' | 'COL', index: number }`). Сервер транслирует его всем участникам комнаты через `broadcastRaw` без модификации внутреннего состояния `gameState`, благодаря чему экран ТВ мгновенно отображает live-подсветку линии.

3. **Игровые действия (Клиент ➔ Сервер, передаются в `gameReducer`):**
   - Действия активного хода: `SHIFT_BOARD` (выполнение маневра линии поля), `TARGET_KILL` (ликвидация маньяка), `CHECK_ALIBI` (проверка алиби детективом), `ARREST` (задержание подозреваемого), `STEAL` (кража сокровища вором), `DISGUISE` (смена маскировки), `CALL_PATROL` (вызов патруля), `CAPTURE_SPY` (разоблачение резидента), `INTERROGATE_SPY` (опрос свидетелей на радаре).
   - *Серверная валидация:* Сервер строго проверяет очерёдность хода (`NOT_YOUR_TURN`), роль отправителя и фазу раунда.
   - *Инвариант безопасности:* Соединению `TV_DISPLAY` запрещено отправлять любые игровые действия (все они блокируются сервером; единственное исключение для ТВ — запуск матча `START_MATCH`).

4. **Серверные ответы и оповещения (Сервер ➔ Клиент / Broadcast):**
   - `AUTH_TOKEN` — криптографический токен сессии для восстановления при разрыве связи.
   - `ROOM_RESOLVED` / `RESOLVE_FAILED` — ответ клиенту на запрос `RESOLVE_ROOM`.
   - `ROOM_STATUS` — широковещательное обновление списка участников, готовности и кода Морзе.
   - `GAME_STATE` — трансляция авторитетного состояния игры после применения действия в `gameReducer` (персонально маскируется для каждого клиента и для ТВ).
   - `ACTION_REJECTED` — отказ в выполнении действия с указанием конкретной причины (`NOT_YOUR_TURN`, `NOT_HOST`, `INVALID_ACTION_FOR_MODE`).
   - `ERROR` — сетевые ошибки (`MAX_TV_REACHED`, `ROOM_FULL`, `ROOM_NOT_FOUND`).

## 4. Безопасность и античит (Многоуровневый комплекс «Стальной Щит»)

Комплекс безопасности игры спроектирован по принципу эшелонированной обороны (Defense-in-Depth):

### 4.1. Серверная фильтрация состояния (State Masking & Cheat Prevention):
Перед трансляцией состояния клиентам через WebSocket сервер выполняет обязательную фильтрацию:
1. **`maskStateForPlayer(state, role, isHost)`:**
   - Скрывает секретные ID персонажей соперника (`killerSecretId` / `detectiveSecretId` / чужие `spies[i].secretId`).
   - Очищает руки карт оппонента (`detectiveHand` / `killerHand` / `thiefHand`).
   - Очищает колоду улик (`evidenceDeck`).
   - Маскирует будущие цели маньяка в очереди `victimList` строками `"UNKNOWN"`, оставляя открытой только текущую цель `[0]`.
2. **`maskStateForTv(state)`:**
   - Полностью очищает все секретные роли, колоды и руки, так как экран ТВ публичен.
   - Оставляет только общее поле 5×5, статус хода, открытые жетоны и протокол действий.
3. **Защита сокета TV_DISPLAY:**
   - Сервер блокирует любые игровые действия, если они отправлены с соединения ТВ.
4. **Авторитетный банк матча (Match Pot):**
   - Клиентские команды `SET_MATCH_POT` блокируются сервером. Банк рассчитывается строго сервером.

### 4.2. Безопасность базы данных Supabase (RLS, Column Grants & Trigger):
1. **Ограничение уровня колонок (Column-Level Grants):**
   - Прямой `UPDATE` для роли `authenticated` разрешён ТОЛЬКО для полей `agent_name` и `avatar_id`.
2. **Триггер `protect_profile_stats`:**
   - Любая попытка подделать `mmr`, `cash`, `xp`, `level`, `rank`, `matches_played` или счетчики побед блокируется на уровне ядра PostgreSQL (код `42501`, 403 Forbidden).
3. **Хранимая функция (RPC) `record_match_result` с античитом:**
   - **Анти-спидхак:** Проверяет `duration_seconds > 10`. Мгновенные победы отклоняются (код `P0001`, 400 Bad Request).
   - **Анти-повтор (Anti-Replay):** Уникальный композитный индекс `(match_id, profile_id)` исключает повторную отправку победы за один и тот же матч (код `23505`, 409 Conflict).

### 4.3. Сетевой валидатор пакетов (P2P / PartyKit):
1. **Функция `parseAndValidatePacket(raw)`:**
   - Проверяет синтаксис типа пакета по белому списку формата `/^[A-Z0-9_]{3,50}$/`.
   - Защита от **Prototype Pollution**: строки, содержащие ключи `"__proto__"`, `"constructor"` или `"prototype"`, отбрасываются (Drop) без парсинга.
   - Блокировка XSS: пейлоады с тегами `<script>` или инъекциями кода отсекаются до передачи в редьюсер.

### 4.4. Изоляция DevTools в Production:
- Компонент отладки `DevPanel` и читы обёрнуты в проверку `if (import.meta.env.DEV)`.
- Сборщик Vite при компиляции `npm run build` физически исключает код дев-панели из клиентского бандла (0 байт в продакшене).

## 5. Хранилище данных и облачная синхронизация (Storage Architecture)

Система построена по гибридной архитектуре **Offline-First с облачной синхронизацией**:
1. **Локальное хранилище:** `IndexedDB` (база `requiem_game_db`, хранилище `key_val`) с автомиграцией и безопасными обёртками `safeLocalStorage` / `safeSessionStorage`. Игра сохраняет 100% автономность без подключения к сети.
2. **Облачная база (Supabase):** 
   - Таблицы `profiles`, `matches`, `match_participants`.
   - Авторизация по логину/паролю без сбора Email-адресов (`@noir.local`).
   - Рейтинговая система (MMR), история матчей и таблица лидеров.
3. **Отказоустойчивость (Graceful Degradation):**
   - При отсутствии переменных `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` клиент плавно переключается на встроенный mock-клиент без сбоев интерфейса.

## 6. Звуковая система, тактильный отклик, PWA и CI

- **Аудиосистема (`soundManager` в `src/utils/audio.ts`):**
  - **2 независимых SFX-канала:** UI-канал (`click`, `confirm`, `error`) и Action-канал (`slide`, `kill`, `arrest`, `steal`, `patrol`, `disguise`, `radar`, `win`).
  - **Анти-наложение:** запуск любого Action-звука принудительно останавливает текущий UI-звук и предыдущий Action-звук (`try/catch`).
  - **Микро-дебаунс 70 мс:** предотвращает наслоение одинаковых звуков при повторных кликах.
  - **Аудиобиблиотека:** строго 25 оригинальных mp3 сэмплов из папки `public/sounds/`. Процедурный синтез через `createOscillator` полностью запрещён регламентом проекта.
- **Тактильный отклик (`src/utils/haptics.ts`):** Использует Capacitor Haptics с безопасным каскадом веб-фоллбэков (`navigator.vibrate`).
- **PWA (Progressive Web App):** Настроен через `vite-plugin-pwa`. Включает компонент `PwaUpdateToast.tsx` (`registerType: "prompt"`), гранулярный код-сплиттинг `manualChunks` и кэширование 105 ассетов (~5.0 МБ) для полной офлайн-работы.
- **CI/CD:** Автоматический сьют проверок на GitHub Actions (`.github/workflows/ci.yml`), валидирующий TypeScript, линтер и 618 тестов Vitest при каждом push и pull request.

## 7. Фронтенд-архитектура визуального слоя и дизайн-системы Neo-Noir

1. **Цветовая палитра и инварианты:**
   - **Базовый фон:** глубокий угольно-черный `#080a0f` и `#06070a`, монохромные оттенки `zinc-100`..`zinc-900`.
   - **Сторона Закона (Детектив, Оперативник, Система):** благородный глубокий сапфирово-синий (`#1E3A8A`, `#2563EB`, `#3B82F6`).
   - **Сторона Преступника / Угрозы:** приглушенный темно-бордовый и глубокий рубиновый (`#2d0814`, `#881337`, `#E11D48`).
2. **Строгие визуальные ограничения:**
   - ❌ **Категорический запрет системных цветных эмодзи:** в интерфейсе разрешены строго монохромные SVG-иконки из UI Kit (`Icons.tsx`, `ProfileIcons.tsx`).
   - ❌ **Запрет циана и неонового киберпанка:** запрещены классы `cyan-*`, токен `accent-neon` и устаревшие тени `shadow-neon-*`.
   - ❌ **Touch Targets $\ge 44\times 44\text{px}$** на всех мобильных экранах с обязательным учётом iOS Safe Area (`100dvh`).
