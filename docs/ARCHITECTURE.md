# Архитектура проекта

## 1. Технологический стек

- **Frontend:** React 18, TypeScript, Vite.
- **Стилизация:** Tailwind CSS.
- **Анимации:** Framer Motion.
- **Backend / Сеть:** Firebase (Auth, Realtime Database).

## 2. Сетевой слой (Firebase)

Вся сетевая логика инкапсулирована в классе `MultiplayerService` (файл `src/utils/multiplayerPeer.ts`).

- **Авторизация:** Используется анонимная авторизация Firebase. Реализован ленивый метод `ensureAuth()` с кэшированием промиса, который гарантирует наличие токена перед любым обращением к БД.
- **Realtime Database:**
  - `/public_rooms` — метаданные открытых комнат для лобби.
  - `/rooms/$roomId` — состояние конкретной комнаты.
  - `/rooms/$roomId/actions` — очередь игровых действий (GameActions).
- **Синхронизация:** Клиенты обмениваются сериализованными объектами `GameAction`.

## 3. Управление состоянием

- **Игровое ядро:** Состояние игры (`GameState`) обновляется исключительно через чистую функцию `gameReducer` (`src/utils/gameReducer.ts`), которая принимает текущее состояние и `GameAction`.
- **Игровая логика:** Вынесена в `src/utils/gameLogic.ts`. Функции логики чистые, возвращают новый объект состояния.
- **Профиль игрока:** Управляется локальным хуком `usePlayerProfile.ts` (сохранение в `localStorage`).

## 4. Взаимодействие UI и логики

- **Компоненты:** Главный компонент `App.tsx` управляет подписками на сеть и локальным стейтом. Он передает данные в `GameBoard.tsx`, который рендерит сетку из `CharacterCard.tsx`.
- **ИИ-боты:** Логика ботов вынесена в `src/utils/aiLogic.ts`. В одиночном режиме `App.tsx` отслеживает смену хода и через `setTimeout` запрашивает ход у ИИ, после чего диспатчит результат в редьюсер.
