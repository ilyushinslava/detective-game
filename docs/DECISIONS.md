# Принятые архитектурные решения (ADR)

## 1. Ленивая авторизация Firebase (ensureAuth)

- **Контекст:** Глобальный синхронный вызов `signInAnonymously` на верхнем уровне модуля приводил к состояниям гонки и падениям при инициализации сети.
- **Решение:** Внедрен метод `ensureAuth()` внутри `MultiplayerService`. Он кэширует промис авторизации и вызывается только перед фактическим обращением к базе данных. При ошибке промис сбрасывается, позволяя повторить попытку.

## 2. Асинхронное отключение (disconnect)

- **Контекст:** При выходе хоста из комнаты синхронный вызов `remove()` не всегда успевал отработать до размонтирования компонента, оставляя «зависшие» комнаты в лобби.
- **Решение:** Метод `disconnect()` сделан асинхронным. Используется `Promise.all` с перехватом ошибок `.catch(() => {})` для гарантированного удаления узлов из `/rooms` и `/public_rooms` перед созданием новой сессии.

## 3. Отказ от нативных диалогов (alert)

- **Контекст:** Использование `alert()` блокировало главный поток браузера, ломало UX и могло вызывать рассинхронизацию сетевых сокетов.
- **Решение:** Создан легковесный компонент `<Toast />` на Tailwind CSS. Он интегрирован в `App.tsx` и `MainMenu.tsx` для неблокирующего отображения ошибок без необходимости тянуть тяжелые библиотеки вроде `react-toastify`.

## 4. Атомарное версионирование и ревью

- **Контекст:** Сложная логика игры требует высокой надежности при внесении изменений.
- **Решение:** Все изменения вносятся строго через формат минимальных диффов («НАЙТИ -> ЗАМЕНИТЬ НА»). Код проверяется независимым ИИ-ассистентом перед коммитом в основную ветку.
