# Реестр дефектов и технический статус проекта (The Wicked City)

Данный документ содержит итоговый отчет аудита безопасности, сетевого детерминизма и игровой логики проекта «Город грехов / Реквием».

---

## 1. Сетевой транспорт, Firebase и безопасность

| ID | Область | Описание дефекта | Решение / Статус |
| :--- | :--- | :--- | :--- |
| **AUD-04** | Firebase Rules | Перекрытие прав записи на уровне узла `$roomCode` позволяло гостю перезаписывать `gameState` | **RESOLVED**: Корневой `.write` ограничен созданием/удалением хостом. Дочерние поля (`guestId`, `guestConnected`, `gameState`, `actions`) защищены явными правилами. |
| **AUD-05** | RTDB Rules | Отсутствие валидации размера пакетов в узле `actions` | **RESOLVED**: Внедрено правило `.validate` на длину `actionJson` (< 1000 симв.) и `senderClientId` (< 100 симв.). |
| **AUD-08** | Экономика | Асинхронное списание ставки в `reserveBet` вызывало гонку состояний | **RESOLVED**: Метод `reserveBet` переписан на синхронную проверку и списание баланса профиля перед стартом. |
| **AUD-09** | Профиль | Слияние профиля через `Math.max(cash)` приводило к несгораемому балансу | **RESOLVED**: Баланс `cash` из облака принимается авторитетно. `Math.max` оставлен строго для несгораемого опыта (`xp`) и уровня. |
| **AUD-10** | Лобби RTDB | Скачивание всех комнат через `onValue` на корне `public_rooms` (утечка трафика) | **RESOLVED**: Запрос ограничен выборкой последних 50 активных комнат через `query(ref, limitToLast(50))`. |
| **NEW-06** | Firebase Rules | Ошибка схемы правил: валидация `users/$uid` требовала несуществующие поля `coins` и `rating` | **RESOLVED**: Правила обновлены под реальную модель `UserProfile` (`cash`, `xp`, `level`). |
| **NEW-07** | Сессия / F5 | Повторный накат старой очереди экшенов при перезагрузке вкладки (F5) | **RESOLVED**: Внедрена метка `sessionRestoredAt`, отсекающая устаревшие экшены из прошлого при повторной подписке. |
| **NEW-08** | Сеть | Накопление истории экшенов от прошлых раундов ломало реванш | **RESOLVED**: В `broadcastMatchStart` добавлена обязательная очистка узла `actions` перед стартом новой партии. |
| **NEW-11** | Редьюсер | Блокировка экшенов реванша (`REQUEST_RESTART`, `MATCH_STARTED`) при `state.winner !== null` | **RESOLVED**: Внедрен белый список системных экшенов `ALLOWED_AFTER_WIN`, обрабатываемых независимо от победителя. |
| **NEW-12** | Тесты | Неполные моки RTDB (`push`, `onChildAdded`, `runTransaction`) в тестах мультиплеера | **RESOLVED**: Экспорты моков актуализированы, добавлен интеграционный тест жизненного цикла реванша. |
| **NEW-14** | Сессия | Потеря режима игры при восстановлении после F5 | **RESOLVED**: Поле `mode` сериализуется в `mp_session` и восстанавливается с наивысшим приоритетом. |
| **NEW-18** | Сеть | Удаление комнаты при F5 из-за `onDisconnect(roomRef).remove()` | **RESOLVED**: Удаление комнаты по `onDisconnect` снято; удаляется только публичная запись лобби. |
| **NEW-20** | Сеть | Ложный дисконнект при выходе через меню | **RESOLVED**: Метод `leaveRoom` гарантированно удаляет стол из `public_rooms` и переводит комнату в `CLOSED`. |

## 4. Архитектурные ограничения системы

1. **Peer-to-Peer топология через RTDB:** Игра функционирует без выделенного authoritative-сервера на базе клиент-хост архитектуры. Хост выступает источником правды для начального состояния поля, колоды и очередности ходов.
2. **Безопасность тайных ролей:** Секретные идентификаторы (`killerSecretId`, `detectiveSecretId`) присутствуют в объекте `GameState` в зашифрованном / сериализованном виде в базе данных. Полная защита от читерства при вскрытии сетевых пакетов требует перехода на Cloud Functions в будущих релизах.
