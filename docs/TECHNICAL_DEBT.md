## 2. Потенциальные риски

### DEBT-02: Локальная LAN-маршрутизация QR-кода в TV Party
- **Категория:** Сеть и подключение телефонов.
- **Файлы:** `src/components/tv/TvLobbyView.tsx`.
- **Подтверждение в коде:** QR-код для подключения телефонов генерируется на основе `window.location.origin`. Если ТВ запущен локально по адресу `localhost:5173`, телефон в домашней сети Wi-Fi не сможет подключиться по адресу `localhost`.
- **Статус:** `POTENTIAL_RISK`.
- **Приоритет:** Средний (P2).
- **Риски:** Ошибка подключения контроллера при локальном тестировании без облачного стенда. (В продакшене на GitHub Pages / Render проблемы нет, так как домен публичный).
- **Рекомендация:** Добавить возможность ручного ввода локального IP-адреса хоста в DevPanel или автоматическое предупреждение в лобби ТВ.

### DEBT-03: Проверка полномочий при подтверждении рестарта (CONFIRM_RESTART)
- **Категория:** Сетевая безопасность / Авторизация действий.
- **Файлы:** `src/server/index.ts` (строки 496–525).
- **Описание:** Статический аудит обнаружил потенциальное отсутствие проверки полномочий отправителя при обработке действия `CONFIRM_RESTART`. В коде сервер переводит комнату в статус `READY_TO_START` и сбрасывает игровое состояние без явной валидации того, кем именно было отправлено подтверждение.
- **Статус:** `POTENTIAL_RISK` (не считается подтверждённой уязвимостью до практического воспроизведения в тестах).
- **Обоснование риска:** В штатном интерфейсе действие отправляется через окно реванша (`RematchModal`), однако прямой сетевой вызов WebSocket гипотетически может быть послан гостевым клиентом после завершения матча.
- **Риски:** Возможность несанкционированного перезапуска матча гостем без явного согласия хоста.
- **Требуемое действие:** Провести отдельную проверку сценария с гостевым клиентом через новый тест в `serverSecurity.test.ts`. При подтверждении — внедрить валидацию аналогично `START_MATCH`. Серверный код в рамках текущей задачи не изменяется.

## 3. Необходимые проверки на физических устройствах (Runtime)

### DEBT-04: Изоляция тач-событий при открытых модальных окнах (BOARD-01)
- **Категория:** Мобильный UI / Тач-взаимодействие.
- **Файлы:** `src/components/GameBoard.tsx`, `src/index.css`.
- **Подтверждение в коде:** В коде задан `pointer-events-auto` и CSS-свойства `-webkit-user-select: none`. Однако на реальных смартфонах (Safari iOS / Chrome Android) свайпы пальцем по открытому модальному окну могут случайно передаваться на фоновое поле.
- **Статус:** `RUNTIME_UNVERIFIED`.
- **Приоритет:** Средний (P2).
- **Риски:** Случайный сдвиг ряда игроком во время чтения описания роли или улик.
- **Рекомендация:** Проверить на физическом iPhone и Android, при необходимости добавить `touch-action: none` для подложек модальных окон.

### DEBT-05: Разблокировка AudioContext и тактильного отклика на iOS
- **Категория:** Мультимедиа / Haptics.
- **Файлы:** `src/utils/audio.ts`, `src/utils/haptics.ts`.
- **Подтверждение в коде:** Звуковая подсистема готова к разблокировке контекста первым тапом. Браузер Safari на iOS исторически блокирует `navigator.vibrate`.
- **Статус:** `RUNTIME_UNVERIFIED`.
- **Приоритет:** Низкий (P3).
- **Риски:** Отсутствие звука при первом клике на iPhone без предварительного жеста пользователя.
- **Рекомендация:** Провести физический тест на мобильном Safari, убедиться в наличии фолбеков без падения приложения.

### DEBT-06: Читаемость мелких шрифтов на 4K экранах ТВ
- **Категория:** TV UI / Доступность.
- **Файлы:** `src/components/tv/TvBoardView.tsx`.
- **Подтверждение в коде:** Некоторые бейджи и номера персонажей используют размер текста `text-[10px]` и `text-[11px]`.
- **Статус:** `RUNTIME_UNVERIFIED`.
- **Приоритет:** Средний (P2).
- **Риски:** Текст может быть трудночитаем с дивана на расстоянии 3–4 метров от телевизора.
- **Рекомендация:** Оценить читаемость на реальном ТВ-экране, при необходимости масштабировать базовый rem для медиа-запросов ТВ.
