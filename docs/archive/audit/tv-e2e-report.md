## 1. Резюме прогона (Executive Summary)

В ходе живого многопользовательского E2E-тестирования ТВ-режима подтверждены отличные результаты по эргономике вёрстки, строгому отсутствию скролла на 720p/1080p и смартфонах 375px/390px, а также отсутствие устаревшего режима `LINE_UP`. 

В то же время выявлены **2 критических архитектурных бага**, блокирующих завершение игрового цикла без ручного вмешательства:
1. **Каскадное самоуничтожение сессии (Cascade Session Teardown):** При подключении второго игрока (Гостя) сервер переводит статус комнаты в `READY_TO_START`, что вызывает нежелательный перезапуск React-эффекта на телефоне Хоста с потерей токена авторизации. Сервер отклоняет соединение Хоста (`UNAUTHORIZED_SESSION`), считает его ушедшим и рассылает событие `OPPONENT_LEFT`. Гость, получив `OPPONENT_LEFT` в лобби, ошибочно расценивает его как отключение ТВ-хоста и принудительно сбрасывает свою сессию в главное меню.
2. **Изоляция стейта игроков на контроллерах (Missing Players Sync):** В обработчике `roomStatus` контроллера в `src/App.tsx` обновляется только статус комнаты, а список подключённых игроков (`tvPlayers`) и их готовность (`tvReadyClients`) не синхронизируются. Из-за этого кнопка Хоста «НАЧАТЬ МАТЧ» остаётся навечно заблокированной (`disabled`) с текстом «ОЖИДАНИЕ ГОТОВНОСТИ (2/2)».

## 3. Реестр выявленных дефектов

### БАГ #1 (CRITICAL): Каскадное самоуничтожение сетевой сессии в лобби
- **Файлы:**
  - [src/App.tsx](file:///c:/Projects/detective-game/src/App.tsx#L217-L296)
  - [src/utils/partyPeer.ts](file:///c:/Projects/detective-game/src/utils/partyPeer.ts#L491-L514)
  - [src/server/index.ts](file:///c:/Projects/detective-game/src/server/index.ts#L612-L623)
- **Причина:**
  1. В `App.tsx` (строка 296) в массиве зависимостей эффекта контроллера стоит `controllerRoomStatus`:
     ```tsx
     }, [clientTypeParam, tvRoomCode, controllerRoomStatus]);
     ```
  2. Когда подключается второй игрок, сервер меняет статус с `"WAITING"` на `"READY_TO_START"`.
  3. Хук Хоста пересоздаётся и вызывает `partyService.connect(...)`.
  4. Метод `connect()` в `partyPeer.ts` видит существующий сокет и вызывает `this.disconnect()`, который стирает `this.authToken = null` и удаляет ключ из `safeSessionStorage`.
  5. Новый сокет подключается к серверу с тем же `clientId`, но без токена (`authToken=`).
  6. Сервер видит, что для `clientId` уже зарегистрирован токен, а входящий пуст — и отклоняет сокет: `UNAUTHORIZED_SESSION`.
  7. Сервер считает Хоста отключившимся и шлёт Гостю `OPPONENT_LEFT`.
  8. Гость в `App.tsx` (строка 244) имеет логику:
     ```tsx
     if (action?.type === "TV_DISCONNECTED" || action?.type === "OPPONENT_LEFT") {
       if (controllerRoomStatus !== "PLAYING") {
         handleLeaveControllerLobby("ТВ-хост отключился");
       }
     }
     ```
     Гость ошибочно считает уход оппонента в лобби «отключением ТВ-хоста» и вылетает в главное меню.
- **Необходимый фикс:**
  - Убрать `controllerRoomStatus` из массива зависимостей эффекта подключения контроллера в `App.tsx` (или использовать реф).
  - В `partyPeer.ts` при переподключении не затирать сохранённый `authToken`, если комната та же.
  - В `App.tsx` разделить обработку `TV_DISCONNECTED` (ТВ ушёл — выход) и `OPPONENT_LEFT` (соперник вышел из лобби — остаёмся в лобби и ждём нового).

### БАГ #2 (CRITICAL): Отсутствие синхронизации игроков и готовности на контроллерах
- **Файлы:**
  - [src/App.tsx](file:///c:/Projects/detective-game/src/App.tsx#L229-L241)
  - [src/App.tsx](file:///c:/Projects/detective-game/src/App.tsx#L1185)
- **Причина:**
  В `App.tsx` (строки 229–241) в `unsubRoomStatus` контроллера обрабатывается только:
  ```tsx
  if (data?.status) {
    setControllerRoomStatus(data.status);
    if (data.status === "PLAYING") setIsIntroPhase(true);
  }
  ```
  При этом поля `data.players`, `data.readyClients`, `data.mode`, `data.roleDistribution` игнорируются! Они обновляются только в эффекте ТВ-экрана (строки 313–336).
  В результате на контроллере Хоста:
  - `tvPlayers` всегда `{}` (длина 0);
  - `tvReadyClients` всегда пустой `Set(0)`;
  - Проп `canStartMatch={Object.keys(tvPlayers).length >= 2 && tvReadyClients.size >= 2}` всегда `false`;
  - Кнопка «НАЧАТЬ МАТЧ» на смартфоне Хоста навечно заблокирована в состоянии `ОЖИДАНИЕ ГОТОВНОСТИ (2/2)`.
- **Необходимый фикс:**
  Добавить в обработчик `roomStatus` контроллера вызовы `setTvPlayers(data.players)`, `setTvReadyClients(new Set(data.readyClients))`, `setTvSelectedMode(data.mode)` и `setTvRoleDistribution(data.roleDistribution)`.

### БАГ #3 (MEDIUM): Ошибки CORS и спам в консоли при запросе комнат лобби
- **Файл:**
  - [src/utils/partyPeer.ts](file:///c:/Projects/detective-game/src/utils/partyPeer.ts#L861)
- **Причина:**
  В `partyPeer.ts` (строка 861) выполняется запрос:
  ```ts
  fetch(`${httpProtocol}//${host}/parties/lobby?action=list`)
  ```
  В PartyKit именованные парти требуют указания комнаты: `/parties/:party/:room`. Запрос без сегмента комнаты возвращает `404 Not Found` без заголовка `Access-Control-Allow-Origin`, из-за чего браузер на всех экранах каждые 3 секунды фиксирует ошибку CORS:
  `Access to fetch at 'http://localhost:1999/parties/lobby?action=list' has been blocked by CORS policy`.
- **Необходимый фикс:**
  Использовать каноничный путь `/parties/lobby/main?action=list` (который возвращает `200 OK` с `Access-Control-Allow-Origin: *`).

### БАГ #4 (LOW): Зависание экрана заставки «НАЖМИТЕ В ЛЮБОМ МЕСТЕ» на веб-ТВ
- **Файл:**
  - [src/App.tsx](file:///c:/Projects/detective-game/src/App.tsx#L768)
- **Причина:**
  В `App.tsx` проп `isTv` у `<SplashScreen>` передаётся как `isAndroidTv`:
  ```tsx
  <SplashScreen
    isTv={isAndroidTv}
    autoDismissDelayMs={isAndroidTv ? 2500 : undefined}
    onComplete={() => setShowSplash(false)}
  />
  ```
  В веб-браузере на ПК или Smart TV `clientTypeParam === "TV_DISPLAY"`, но `isAndroidTv` равен `false`. Заставка ждёт клика или пробела, перекрывая ТВ-лобби (`z-[100]`), пока пользователь не нажмёт на экран.
- **Необходимый фикс:**
  Передавать `isTv={isAndroidTv || clientTypeParam === "TV_DISPLAY"}` и `autoDismissDelayMs={isAndroidTv || clientTypeParam === "TV_DISPLAY" ? 2500 : undefined}`.
